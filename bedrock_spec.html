2. Kiến trúc tổng thể

5. Pipeline order

Passes được đăng ký qua _insert_after_obf_vars — reverse stack: pass khai báo LATER chạy EARLIER. Order thực tế (normal mode):

1. obf_vars              ← identifier renaming (anchor)
2. strfrag2              ← string fragmentation v2
3. import_obf            ← import obfuscation
4. native_vm             ← Phase 5: BedrockVM compile (claim functions FIRST)
5. runtime_dec           ← Phase 1: capsule runtime (skip VM-claimed funcs)
6. var_split             ← XOR secret-sharing
7. dec_trap              ← decompiler traps
8. junk                  ← junk code + opaque predicates
9. boolobf               ← True/False/None obfuscation
10. numobf               ← integer literal obfuscation
11. lambda_enc           ← def → lambda
12. homoglyph            ← Unicode homoglyph renaming
13. cff                  ← control-flow flattening (LAST ext pass)
14. plugins:after_rename
15. vm_strings           ← VM string encoding
16. obf_builtins         ← builtin indirection
17. obf_strings          ← string obfuscation
18. plugins:pre_compile
19. Compile.Obfuscate    ← marshal + integrity hash + anti-pycdc
Critical fix (P7.8): apply_native_vm marks wrappers với _bedrock_vm_claimed = True; _runtimedec_collect_targets skip các function có mark này → tránh capsule-wrap VM wrapper (deadlock khi chain shard re-install __code__ trong khi VM đang chạy).

--runtime-dec | auto-on cho extreme

Cơ chế

  1. Capture __code__ thật của mỗi eligible function (_real)
  2. Marshal + encrypt với per-capsule 32-byte key (SHA-256 OFB stream cipher)
  3. Install no-op stub (_stub) làm __code__
  4. Wrap globals()[name] với wrapper _w: mỗi call → decrypt _enc → swap __code__ → run → restore stub trong finally
RAM window: Bytecode decrypt chỉ tồn tại trong RAM trong lúc gọi. Static memory dump giữa 2 call chỉ thấy no-op stub.

Eligibility

  • Top-level def only (không nested, không async, không yield/await)
  • Skip dunders (__init__, etc.)
  • Skip entry guard (function body có __name__ / "__main__")
  • Skip VM-claimed functions (có _bedrock_vm_claimed — fix P7.8)
  • Fail-safe: lỗi per-function → __code__ giữ nguyên

9. P3 Phase 3 — Debug Poison + Metamorphic

Debug Poisoning (--debug-poison)

  • Anti-dbg/anti-vm/tamper reactions route qua __h_poison(tag, weight) thay vì sys.exit
  • Force tamper_mode = 'poison'
  • Auto-enable --chain (poison state lives trong integrity shard)
  • Net effect: debugger detected → program vẫn chạy nhưng mọi downstream capsule decrypt ra garbage (silent inert). Attacker có "working" program nhưng output sai.

Metamorphic (--metamorphic)

  • 5th shard _br_meta_shard re-read __file__ mỗi import
  • Insert fresh # meta<48 hex> comment sau __H_FILE_HASH__ line
  • Re-mask cả file hash + integrity hash → 64 dots, recompute với salt |fh / |int
  • Atomic os.replace qua .meta temp file
  • On-disk artifact khác bytes mỗi run, logic payload byte-for-byte identical
  • Fail-safe: lỗi → __h_poison('meta_fail', 7), không crash

10. P4 Phase 4 — Anti-meta Debrand

--anti-meta | auto-on cho extreme

  • Kết quả: grep -ic bedrock trên output = 0 (verified)

11. P5 Phase 5 — Native BedrockVM

--native-vm | auto-on cho extreme

11¾. Phase iO — Practical Indistinguishability Obfuscation

Phase iO nâng obfuscator lên Practical iO grade — hai builds của cùng chương trình computationally indistinguishable từ random data. Target: nation-state + academic adversaries. No performance constraint.

Kết quả iO-7 (binary capsule): Shannon entropy 7.96 bits/byte, pairwise chi-square mean 501 (random baseline ~510±35), ML classifier accuracy 40% (IO_SPEC.md.

Binary Capsule (iO-7) — How it works

The binary capsule wraps the entire obfuscated source in an encrypted container:

  1. Compress the source (zlib level 9).
  2. Encrypt with a per-build 32-byte key (SHA-256 CTR-mode XOR keystream).
  3. Prepend the key to the encrypted blob (first 32 bytes = key, rest = encrypted data).
  4. Embed as a latin-1 triple-quoted string literal in a ~10-line bootstrap.
  5. The bootstrap reads the blob, extracts the key, decrypts, decompresses, and execs the original source.

The resulting file is ~99.9% encrypted data (uniform byte distribution) and ~0.1% bootstrap. The pairwise chi-square approaches the expected value for two independent random samples (~510), achieving statistical indistinguishability from random data.

Per-build opcode permutation

Mỗi build generate bijection perm: scrambled_byte → canonical_byte. Blob chứa scrambled opcodes; interpreter de-scramble trên dispatch. Perm table không ở trong blob — nó ride trong .py loader như Python dict, passed riêng cho run(). EXTENDED_ARG (canonical 144) là fixed — scrambled byte perm_ext baked vào cả perm table lẫn interpreter.

Consequence: 2 builds cùng source produce khác opcode bytes → static signature của build A không match build B. De-scramble cần perm, riêng biệt khỏi blob.

14. Encryption — SHA-256 OFB

Symmetric (encrypt == decrypt). Reuses obfuscator's _br_decrypt. Áp dụng cho cả const pool VÀ names blob, nhưng với key khác nhau để tránh two-time pad.

state_0 = sha256(key).digest()
state_n = sha256(state_{n-1} + key + bytes([offset & 255])).digest()
ciphertext[i] = plaintext[i] ^ state_n[i % 32]

offset = byte offset vào pool ở start của 32-byte keystream block. Mỗi block advance offset 32.

Two-time pad avoidance: const pool và names blob đều bắt đầu ở OFB offset 0. Nếu dùng cùng key, XOR hai ciphertext → const_pickle XOR names_pickle (exploitable vì names là structured pickle). Nên names blob dùng derived key: 
names_key = sha256(key + b'|names').digest()
OFB length-preserving → len(encrypted) == len(plaintext_pickle), nên names_len trong blob header không đổi. key=b'' (test blobs): names stored plaintext (backward compat).
